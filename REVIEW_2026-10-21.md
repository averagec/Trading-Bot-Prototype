# forex_bot — five-persona review (merged)

Reviewers: software engineer, quant trader, experienced prop-firm trader, AI/ML engineer, beginner.
All read-only. No project files were changed. Findings are from code reading, `forex_bot.log`,
`pair_data.json` and the xlsx; nothing was verified by running the bot. FTMO rules came from
third-party summaries, so check FTMO's own current terms.

## Verdict
Do not run live. There is no valid evidence of edge: the backtest has never produced a result,
no trade has ever closed with a recorded outcome, and the main SMC trigger (liquidity sweep) is dead code.
The scaffolding (MT5-aware sizing, spread/margin validator, currency-exposure cap) is worth keeping.

## Fix first (all five agents agree or it is a confirmed bug)
1. **Rotate the MT5 password** in `config.py` and move secrets to env vars / `.env`. It is plaintext, and
   the optimiser rewrites that file. It also appeared in one agent's tool output during this review.
2. **Liquidity sweep can never fire** — `strategies/smc_strategies.py:283-290`: the lookback window includes
   the candle it is compared against. Fix the window to exclude `prev` (e.g. `iloc[-lookback-2:-2]`).
3. **LLM call has no auth headers** — `agents/llm_agent.py:29-31` sends no `x-api-key` / `anthropic-version`.
   With `ANTHROPIC_API_KEY` set, every call fails and the fallback is HOLD, so trading stops silently.
   Fix, or remove the LLM path. If kept: veto-only, temperature 0, schema-enforced output, log everything.
   Also: LLM can flip trade direction without the checklist being re-run (`main.py:253-254`); model ID
   `claude-sonnet-4-20250514` (`config.py:70`) should be checked against the current model list.
4. **News filter fails open and was off the whole logged run** (2,464 "news blocking disabled" warnings;
   ForexFactory HTTP 429). Make it fail closed, cache the calendar on disk, fetch hourly.
5. **Fail closed on missing data.** `get_account_info` fabricates a $10,000 balance when MT5 is down
   (`mt5_connector.py:200`); a None account skips the risk gate (`main.py:108`); no reconnect logic;
   `order_send` None-results are dereferenced.
6. **Risk limits do not match FTMO and live only in memory.** Daily baseline = first balance seen each UTC day,
   reset on restart (`risk_manager.py:34-51`). FTMO: equity-based, midnight Prague reset. No 10% max-loss
   check. Persist baselines to disk. Add Friday/weekend flatten, consecutive-loss limit, enforce `trades_today`.
7. **Config and README disagree with the code.** Code: 0.5% risk, 3% daily, R:R 3, score >= 50 plus 4/5
   checklist, 5-minute loop. Config/README: 1%, 5%, R:R 2, 65%, 15-minute. Several config keys are never read.
8. **No kill switch / no demo-live guard.** Ctrl+C during the sleep skips `shutdown()` (`main.py:101`);
   open trades remain; nothing checks account type. Add a STOP file, a panic-close script, a typed
   confirmation for live.
9. **Crash bug** `print.info(...)` at `smc_strategies.py:115` (short H1 data).
10. **Pending orders**: GTC with in-memory expiry (orphans after restart); limit orders silently become
    STOP orders when price is on the wrong side (`main.py:407-410`); pending orders not counted as risk.
11. **Excel is on the hot path** — if the workbook is open, the cycle aborts before risk checks
    (`main.py:114`). Make it a best-effort sink; use SQLite as the source of truth.
12. **Pip/lot maths** differs across modules; gold (XAUUSD) sizing looks wrong in the log. Unify via `symbol_info`.

## Backtest / validation (quant + ML)
- The "probability" is a points sum (max ~125), not a probability. Treat it as ordinal only.
- `backtest_engine.py`: forming-bar look-ahead (`:90-91`), `datetime.now()` in quarterly theory (`smc_strategies.py:201`),
  BUY-only legacy wrappers (`:502-515`), no spread/slippage, JPY/gold pip errors, skips entry bar, no
  position lock, rules differ from live. Requires MT5; produced no results.
- `optimiser.py`: no out-of-sample, ~156 configs tested, selects the best, writes into `config.py`. Overfit by construction.
- Data: ~125 independent setups in the signal log (94% of rows repeat the previous row); 12 trades, none closed;
  `record_trade_outcome` is never called, so there are no labels.
- Break-even win rate at 3R is ~25% before costs. Detecting +0.2R needs ~200-450 independent trades.
- Protocol: 5-8 years M1 bid/ask, closed bars only, next-open fills with spread, one position per symbol,
  pre-registered configs (<= 5), anchored walk-forward, final holdout, multiple-testing correction,
  day-block bootstrap, FTMO rule simulation, gate of >= 300 out-of-sample trades.

## Strategy versions to try (none validated)
- **V1 (quant): fix and measure the current signals** — engine fixes, 0.25% risk, total open+pending risk <= 1%,
  2% daily stop, hard kill at -6%, breakeven at 1.5R or removed, no LLM.
- **A (trader): London sweep-and-reverse** on EURUSD/GBPUSD — Asian range sweep, structure break, FVG limit
  entry, stop beyond the wick, TP 2R / opposite extreme, 0.5% risk, max 2 trades/day.
- **B (trader): news avoidance + post-news fade** — flat 30 min before / 15 min after; blocks all trading if calendar is down; 0.25% risk.
- **C (trader): HTF-bias swing** — D1/W1 bias, one decision per day, 2.5% daily kill, Friday flatten.
- **V2 (quant): simple trend-pullback** — H4 EMA50>EMA200 + ADX>20, H1 pullback, M15 confirmation, ATR stop, <= 3 parameters.
- **V3 (quant) / ML V1 (ML): calibrated model or meta-labelling** on rule features, triple-barrier R labels,
  purged walk-forward CV. Needs data regenerated from MT5 history first; realistic uplift 0.05-0.15R/trade.

5. Only then compare versions A / B / C / V2 / ML; forward-test on demo for 4-8 weeks.
